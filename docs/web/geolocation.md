# 現在地の表示と位置情報の許可

地図右下の現在地ボタンで、現在地の点・精度の円を表示し、現在地へ追従する。表示と追従は MapLibre の `GeolocateControl` が行い、許可の案内は `apps/web/app/components/features/Map/` の次のファイルで行う。

| ファイル | 役割 |
| --- | --- |
| `MapControls.tsx` | 現在地ボタン。許可の状態に応じて、説明・設定手順のダイアログを挟んでから取得を始める |
| `LocationPermissionDialog.tsx` | 初回の説明と、拒否されているときの設定手順を出すダイアログ |
| `apps/web/app/lib/geolocation.ts` | 許可状態の購読、アプリ内ブラウザの判定、端末・ブラウザ別の設定手順 |

## ボタンを押したときの流れ

Web ページから位置情報を許可することはできず、ブラウザの確認を出すことしかできない。拒否されたあとは確認も出せないため、設定手順を案内する。

| 状態 | 動作 |
| --- | --- |
| 許可済み | そのまま取得を始める |
| 未決定（初回） | 説明を出し、「表示する」でブラウザの確認を出す。説明には、位置情報を人流解析のため匿名化してサーバーに送信することがある旨を小さく添える。一度承諾した端末では次から説明を省く |
| 未決定（説明を承諾済み） | すぐにブラウザの確認を出す |
| 拒否 | 端末とブラウザに合わせた設定手順を出す |
| 非対応・HTTPS でない | 利用できない旨を表示する |

- 許可状態は Permissions API で取得する。取得できないブラウザでは未決定として扱う。
- ブラウザの確認は、ボタンのクリックの中で同期的に取得を始めて出す。ユーザー操作の外で求めると、iOS Safari では出ず、Chrome では目立たない表示になるため。
- 設定手順を出している間に許可へ変わったら（アドレスバーから許可したときなど）、ダイアログを閉じて取得を始める。
- サイトを許可していても OS 側で位置情報が切られていると拒否のエラーになるため、設定手順には OS の位置情報サービスも含める。

## アプリ内ブラウザ

LINE・Instagram・Facebook・X・TikTok、Android の WebView で開かれているときは、ダイアログに標準ブラウザで開き直す案内を出す。

- LINE: URL に `openExternalBrowser=1` を付けて開き直す
- Android: `intent://` で Chrome を開く
- それ以外（iOS の多くのアプリ）: URL をコピーし、ブラウザに貼り付けて開くよう案内する

## 取得に失敗したとき

- 取得の待ち時間は 15 秒。過ぎたら止めて、もう一度試すよう表示する。
- 追従中の一時的な失敗では止めず、現在地の点を薄く表示したまま次の取得を待つ。
- 会場の外にいるときは止めて、その旨を表示する。

## 動作確認

位置情報は HTTPS（または `localhost`）でしか使えない。スマホの実機では、LAN の開発サーバーではなく HTTPS のプレビュー環境で確認する。
