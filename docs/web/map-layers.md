# 地図上の会場情報

地図スタイル（`apps/web/app/components/features/Map/sohosai-map.json`）の上に、会場エリア・建物・屋外ブース（テント）・ステージを重ねて表示する。実装は `apps/web/app/components/features/Map/` の次のファイル。

| ファイル | 役割 |
| --- | --- |
| `campusData.ts` | 企画・場所から、地図の各ソースに流す GeoJSON を組み立てる |
| `campusStyle.ts` | ソース・レイヤの定義（ズームの段階、色、タップ対象のレイヤ、強調表示） |
| `CampusLayers.tsx` | 地図へのレイヤ追加、データの流し込み、タップでのページ遷移、表示中のページに応じた強調 |
| `booths.ts` | 屋外ブースのテントの形（`data/booths.geojson`）と中心 |

データは `project.list` と `place.list` から作るので、企画や場所が変われば地図も追従する。

建物の輪郭は `data/buildings.geojson` だけに持つ。地図スタイルの平面の建物の塗り（`sohosai-buildings` レイヤ）も、`MapView.tsx` が地図を作るときにソース `sohosai-buildings-fill` をこの GeoJSON に差し替えて描く。スタイル側に別の輪郭を持つと、選択中の強調・タップ判定・3D と形がずれるため、スタイル JSON のこのソースは空にしてある。企画と場所の対応は [企画の実施場所データ](../data/project-locations.md) を参照。

## ズームごとの表示

初期表示と右下の家のボタンでは、画面の大きさによらず会場エリアがすべて収まるところまで引く（スマホのアプリ本体では下部シートの分を空ける）。

地図のレイヤの色は MapLibre が CSS 変数を解釈できないため、`token()` が 16 進の値を返すトークン（別トークンを参照しないもの）だけを使う。参照するトークン（`accent.text` など）を渡すとそのレイヤの追加に失敗し、表示されない。

| ズーム | 表示 |
| --- | --- |
| 〜15.8 | 会場エリア名（第一エリア・第二・第三エリア・大学会館エリア・体芸エリア）と、エリア内の企画数。タップすると、エリア内の企画一覧（`/area/:areaId`）を開き、エリアが収まるところまで寄る。ただし建物のピンに切り替わる 15.8 より引いては止まらず、大きなエリアは端が画面からはみ出す |
| 15.8〜 | 企画のある建物のピン（中に企画数）と、その下に建物名。ステージ名 |
| 15.4〜 | ステージのピン |
| 15.8〜 | 案内所のアイコン（橙の丸に i）と名前。17.6〜18 でアイコンを消しながら案内所のテント（橙）に入れ替える |
| 15.8〜 | 駐車場のアイコン（青の丸に P）と名前 |
| 17.4〜 | ごみ箱のアイコン（緑の丸にごみ箱）と名前 |
| 17.4〜 | 駐輪場のアイコン（紫の丸に自転車）と名前 |
| 17.4〜 | 建物名・ステージ名の下に企画数 |
| 15.8〜18 | 屋外ブースの点（企画の分類の色、ズームしても大きさは一定）。17.6〜18 で点を消しながらテントの形に入れ替える |
| 17.6〜 | 屋外ブースのテント（配置図どおりの形・向き、企画の分類の色） |
| 18.2〜 | 建物名の下に、中の企画名（部屋番号順に3件まで、残りは「ほか N件」） |
| 18.3〜 | テントの横に企画名 |

案内所・ごみ箱・駐車場・駐輪場は `place.list` の `kind: 'information'` / `'trash'` / `'parking'` / `'bicycle_parking'` の場所。駐輪場の位置は、雙峰祭公式サイトの自転車撤去案内にある「自転車の移動先」。案内所のテントの形は `data/information.geojson`（`properties.placeId` が案内所の Place の id）にあり、屋外ブースのテントと同じレイヤ（3D も同じ）で描く。これらはタップしても何も開かない。ごみ箱・駐輪場・駐車場の企画（場所がすべて同じ種類の施設の企画）の詳細では、場所ごとの吹き出しを出さず、その種類のアイコンだけを強調する（埋め込みの `?highlight=` と同じ見せ方。`highlightPlaceKind`）。場所が多く、吹き出しが重なり合って一部しか出ないため。詳細を閉じると元に戻す。名前は他のラベルと重なると省き、アイコンは常に出す。

会場エリアの中のペデストリアンデッキとその広場は、地図スタイル（`sohosai-map.json`）の `pedestrian-paths` ソースに持ち、ズーム 14〜 でベージュに描く。下地の地図スタイルは歩行者道（OpenMapTiles の `path`）を描かないため、別に足している。形は OSM の way（`properties.osmId`）を会場エリア（`area-1` `area-2-3` `area-kaikan` `area-taigei`）で切り抜いたもので、エリアの外の道は持たない。エリアどうしは道路を挟んで離れているため、切り抜く前にエリアを約 40m 膨らませてから同じだけ縮め、すき間だけを埋めている（平塚通りを渡るペデが途中で切れないようにするため）。

| `properties.kind` | OSM のタグ | 描き方 |
| --- | --- | --- |
| `deck` | `highway=pedestrian`（線） | 太線（実際の幅の約 8m）。名前のある線（ペデストリアンデッキ）は、ズーム 16〜 で道に沿って名前を出す |
| `plaza` | `highway=pedestrian` + `area=yes`。ほかに石の広場（`place=square`）と、それと一体の芝生・植え込み | 面 |

`footway` などの細い道は、ペデから離れた所で地図が細かくなりすぎるため描かない。

企画のない所の道は描かない。第二・第三エリアでは 2D棟の北端（緯度 36.11201）より北を切り落とし、人間系学系棟の中庭（w1174321006）・2C棟の東（w560849067）・3A棟の西（w1097264789）の広場は除いている。

会場エリアに掛かる池と水路は、地図スタイルの `campus-water` ソースに面で持ち（元の OSM の way は `properties.osmIds`）、下地の水面と同じ色で重ねる。地図タイルの水面は形が粗く、ペデの広場にも塗りつぶされるため。池は `natural=water` の面、水路は `waterway=stream` の線を幅約 6m の面にしたもの（国土数値情報由来の粗い線 `source=KSJ2` は除く）。水路の端は池の縁に届いていないため、つながる池とまとめて約 4m 膨らませてから縮め、1つの水面にしている。

重なり順は、天久保池などの池はペデの下、第二・第三エリアの水路（`properties.overDeck: true`）はペデの上。この水路はペデの線から数 m しか離れておらず、ペデの幅で描くと隠れるため。

建物の中の企画は、地図上では建物のピンにまとめ、部屋ごとの位置は出さない。ブース番号（`C4` など）は配置のための内部的な番号なので、地図にも一覧にも出さない。

エリアの企画数は、各企画のいずれかの実施場所がそのエリアの範囲に入るかで数える。エリアの範囲は地図スタイルの塗り分け（`area-1` `area-2-3` `area-kaikan` `area-taigei`）を使う。

ズームで文言が変わるラベルは、段階ごとに別のレイヤにしている。symbol の `text-field` に書いた zoom 式はデータのタイルの整数ズームで評価され、小数の境目で切り替わらないため。

## 操作

- タップ位置の周囲 10px にある対象のうち、タップ位置に最も近いもの（テントは中心、ピンはその位置）を選ぶ。
  - テント・ブースの点: そのブースの企画詳細（`/project/:number`）を開く。日によって企画が変わるブースは、テント列の企画一覧を開く。
  - 建物のピン・名前・塗り、ステージのピン: `/place/:placeId`（その場所の企画一覧）を開く。建物は、中の企画が1件以上あるか、中にステージがある（1A棟・大学会館）ときに押せる。
- `/place/:placeId` は、その場所の企画一覧をシートに出し、シートを半分まで開いて地図をその場所へ寄せる（屋外はテントが見えるズーム 18.5）。建物は部屋番号の先頭の数字で階ごとに分け、同じ企画が複数の部屋にまたがるときは1行にまとめる。中にステージがある建物は、その上に「ステージ」の段を置き、ステージ名と企画数を並べる（押すとそのステージのページへ）。見出しの企画数は、建物の企画と中のステージの企画を合わせた数。地図の建物のピンの企画数には、ステージのピンと同じ数が並ばないよう、ステージの企画を含めない。
- 場所ページではその場所（テント列ならその列のテントすべて、建物なら中のステージも）を、企画詳細ではその企画の実施場所とテントを強調する。企画詳細は、屋外ブースならテントの位置へズーム 18.5 で寄せる（テントを隠さないようピンは立てない）。

## 地図右下のボタン

実装は `apps/web/app/components/features/Map/MapControls.tsx`。

- ホーム: 地図を初期表示（会場全体）に戻す。現在地を追従中なら追従だけ外す（現在地の点は残る）。
- 現在地: MapLibre の `GeolocateControl` で現在地の点と精度の円を出し、追従する。押すたびに 表示・追従 → 停止 と切り替わり、地図を動かして追従が外れた状態から押すと追従に戻る。位置情報が許可されていない・取得できない・会場の外にいるときはメッセージを出す。標準の現在地ボタンは隠している。
- 3D/2D: 地図を 60° 傾けた表示と真上からの表示を切り替える。2D に戻すときは北を上に戻す。右ドラッグや2本指で傾けたときも表示が追従する。

PC（幅 768px 以上）では、地図の左に一覧・詳細のサイドパネルを置き、ボタンは地図右下の著作権表記の上に寄せる。パネルを開いている間はパネル分だけ地図に padding を空け、フォーカスや初期表示が見えている範囲の中央に来るようにする。

## 3D 表示

地図が傾いている間だけ、建物とテントを立体（`fill-extrusion`）で描く。実装は `campusStyle.ts` の `addExtrusionLayers` / `setExtrusionVisible`。

| レイヤ | 対象 | 高さ | 不透明度 |
| --- | --- | --- | --- |
| `campus-booth-3d` | 屋外ブースと案内所のテント（ズーム 17.6〜） | 2m | 1 |
| `campus-building-3d` | 会場の建物（`buildings.geojson`） | `levels` × 4m | 1 → 0.45 |

- 立体にするのは会場の建物だけ。地図タイルの建物（会場以外）は平面のまま。
- 軒下や建物の奥のテントが隠れないよう、テントの点が形に入れ替わるズーム（17.6〜18）で、会場の建物の立体をすべて同じ不透明度 0.45 まで下げる。MapLibre の立体の不透明度はレイヤ単位でしか変えられないため、テントに重なる建物だけを透かすと建物によって見え方が揃わない。
- MapLibre の半透明の立体は奥行きを書き込んでから色を塗り、3D のレイヤは奥行きを共有するため、後に描いた立体は半透明の建物の内側に隠れる。そのためテントの立体は建物より先に描く。
- 立体は道路などの平面のレイヤより後、地図スタイルの文字レイヤより前に差し込む。ピン・ラベルは立体の上に描かれる。
- 地面に描く強調（建物の塗り・枠線、テントの枠線）は立体に埋もれるため、3D の間は隠し、選択中の建物はアクセント色、テントは濃いアクセント色の立体で強調する。高さは変えない。
- 隣り合うテントは辺を共有しているため、立体がつながって境界が消えないよう、テントの形を中心に向けて 0.85 倍に縮めて描く（`booths.ts`）。
- タップ判定も、3D の間は地面の塗りではなく立体で取る（傾けた状態で屋根を押しても、その建物が開く）。

## 地図の範囲

動かせる範囲はキャンパス周辺（経度 140.07〜140.135、緯度 36.08〜36.135）、最小ズームは 14。
